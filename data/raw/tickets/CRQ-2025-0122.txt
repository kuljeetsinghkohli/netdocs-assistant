AFFECTED_SITE: All DC Sites

TICKET_TYPE: Standard Change

DESCRIPTION:
Currently, iBGP between hub routers selects a single best path for each prefix and only advertises that path to iBGP peers. This means that if the best-path hub is unreachable, convergence requires BGP to select a new best path, which can take 3–5 seconds even with BFD. Enabling BGP Additional Paths (RFC 7911) allows each hub to advertise up to 4 paths for each prefix to iBGP peers, enabling immediate path selection on failure without waiting for BGP reconvergence.

Expected benefit: BGP convergence on inter-DC path failure improves from ~3 seconds to sub-second.

IMPLEMENTATION PLAN:
On each hub router (all 4 simultaneously — iBGP mesh, all must support ADD-PATH):
   router bgp 65001
    bgp additional-paths send receive
    address-family ipv4 unicast
     bgp additional-paths select backup
     neighbor IBGP-HUBS additional-paths send receive
    exit-address-family
After configuration:
   clear ip bgp IBGP-HUBS soft
Verify:
   show ip bgp 10.10.0.0 255.255.0.0

ROLLBACK PLAN:
Remove additional-paths configuration and soft-reset iBGP.

TEST PLAN:
- show ip bgp: multiple paths visible for key prefixes (LON DC prefix should show 3 alternatives from other hubs).
- Shutdown iBGP link between LON and NYC: traffic should not black-hole — measure convergence time.

REFERENCES: DD-003, RFC 7911
